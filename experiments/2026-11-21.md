# 2026-11-21 · AdsPower 指纹读取路径复测

本轮确认了三处可重复的差异。自定义分辨率造成屏幕读数冲突，WebGL 图像噪声只改变了部分回读结果，自定义字体列表隐藏了普通度量中的 PingFang SC，但 `FontFace local()` 仍能加载。

## 环境与方法

同一台 Apple M4 Mac，系统报告 macOS `27.2.1`，页面缩放 100%，DPR 为 2。AdsPower Global `8.9.23`，补丁 `2.9.0.2`。原测试配置 `FP-Test` 使用 SunBrowser `156.0.8078.36`。新建的桌面 macOS 测试配置 `FP-Local-Validation` 使用 SunBrowser `157.0.8103.15`，客户端首次启动该配置时下载了 157 内核。对照为使用独立数据目录的 Chrome `157.0.8103.79`。

用[本机探针](../tools/probe/README.md)在 `127.0.0.1` 和 `localhost` 上采集主页面、同源 iframe、跨源 iframe 和 Dedicated Worker。每次启动采 3 页，每个改变设置的实验组独立重开两次。每组相对其同配置基线只改一个目标设置。共完成 16 个批次、48 页，192 个执行上下文中收到 191 个结果。唯一缺失是 `lab-1920-2` 第 3 页的跨源 iframe 超时。无重复样本。

## 自定义屏幕分辨率

假设是 `screen` 与 CSS 设备尺寸来自不同的读取路径。对比 `screen.width/height`、`Screen.prototype` getter、`matchMedia()` 的设备尺寸和实际生效的 CSS `@media` 规则。CSS 的设备尺寸与视口尺寸独立测量，同源和跨源 iframe 的视口均为 `320 × 240`。两套规格均将这里的屏幕尺寸定义在网页可见屏幕区域，单位为 CSS 像素。 [CSSOM View](https://www.w3.org/TR/cssom-view/#the-screen-interface) · [Media Queries Level 4](https://www.w3.org/TR/mediaqueries-4/#device-width)

| 设置与内核 | `screen` 与原型 getter | `matchMedia()` 与 CSS 规则 | 复现 |
| --- | --- | --- | --- |
| `1440 × 900`，SunBrowser 156 | `720 × 450` | `1440 × 900` | 18/18 |
| `1440 × 900`，SunBrowser 157 | `720 × 450` | `1440 × 900` | 18/18 |
| `1920 × 1080`，SunBrowser 157 | `960 × 540` | `1920 × 1080` | 17/17 |

三组均在主页面和两类 iframe 复现。53 个有效窗口上下文的 CSS 宽高均等于 `screen` 宽高乘以 DPR。其余 90 个有效窗口上下文的四种读法均一致，Chrome 对照及恢复默认后的 `FP-Test` 均为 `2304 × 1296`。这个差值可用于识别本次自定义模式的屏幕读数不一致。CSS 读取到的是配置宽高，实测覆盖的 DPR 为 2。

## WebGL 图像噪声

SunBrowser 157 保持 Canvas 为 Real，单独开启 WebGL Image Noise。WebGL 1 和 WebGL 2 分别绘制 `96 × 64` 的纯色分区和逐像素可计算的着色器图案。统一读取行顺序后，将每条路径和已知 RGBA 逐像素比较。PNG 直接解码像素，Canvas 2D 路径则使用 `drawImage()` 和 `getImageData()`。WebGL 2 额外通过 `PIXEL_PACK_BUFFER` 及 `getBufferSubData()` 回读。 [Khronos WebGL 规范](https://registry.khronos.org/webgl/specs/latest/1.0/) · [WebGL 2 规范](https://registry.khronos.org/webgl/specs/latest/2.0/)

| 场景和路径 | Chrome 对照 | AdsPower 开启噪声后 |
| --- | --- | --- |
| 着色器，直接写入数组的 `readPixels()`，含两次回读 | 96/96 与预期一致 | 96/96 均改动同一个像素 |
| 着色器，PNG、Canvas 2D 复制、WebGL 2 像素缓冲区 | 120/120 与预期一致 | 120/120 与预期一致 |
| 分段清屏，所有路径 | 216/216 与预期一致 | 216/216 与预期一致 |

从图像左上角计数，坐标 `(0, 63)` 的 `[17, 31, 47, 255]` 在直接数组回读中变成 `[56, 56, 54, 51]`。两次启动、四种执行上下文和两代 WebGL 都复现了同一差异。AdsPower 关闭噪声的 156 和 157 基线共 648 次回读均与预期一致。不同路径的同一像素冲突可以暴露噪声处理，另外三条回读路径在这个场景里保留了原始输出。此图案的预期值由测试程序生成，结果不用于估算 GPU 识别能力。

## 自定义字体列表

SunBrowser 157 保持屏幕预设和 WebGL Image Real，使用界面生成一组 166 项自定义字体。保存后重新打开编辑器，确认列表未包含 `PingFang SC`、`PingFangSC-Regular` 和 `STHeiti`，并保留 `Heiti SC` 与 `PingFang HK`。对固定的 23 个候选字体比较 DOM 文本布局、Canvas `measureText()` 和 `FontFace local()`。`local()` 使用候选字体族的名称和已知的 PostScript 名称。 [CSS 字体源](https://www.w3.org/TR/css-fonts-4/#descdef-font-face-src) · [CSS Font Loading](https://www.w3.org/TR/css-font-loading/#FontFace-interface)

| 字体 | Chrome 和 AdsPower 基线 | AdsPower 自定义 |
| --- | --- | --- |
| `PingFang SC` | 三种读法在可测时均为阳性 | DOM 16/16 回退，Canvas 24/24 回退，`local()` 24/24 可加载 |
| `STHeiti` | 三种读法在可测时均为阳性 | DOM 16/16、Canvas 24/24、`local()` 24/24 仍为阳性 |

`PingFang SC` 的分裂结果跨两次重开稳定。Worker 没有 DOM，另有两次跨源 iframe 的 DOM 字体布局读数不可用。Arial 阳性对照和不存在的字体阴性对照通过。Futura 和 Hiragino Sans 在 Chrome 基线就出现普通度量为阳性而 `local()` 加载失败，所以将同机 Chrome 与同配置基线一起作为对照。

## 存储隔离与浏览器标识

- `FP-Test` 首访时两项标记均为空，写入后重开仍可见。新测试配置访问同一个本机源时，首访两项标记也为空，写入后可在该配置的后续页面读到。再次返回 `FP-Test`，它的原有测试标记仍在。结果支持本次两个配置的 Cookie 和 `localStorage` 隔离。
- JavaScript 与 HTTP 的 User-Agent 和首选语言在 191/191 个可比较上下文中一致。已发出的基础 Client Hints 在 143/143 个上下文中一致，已发出的高熵字段在 96/96 个上下文中一致。Worker 请求未带基础 Client Hints，Worker 和跨源 iframe 请求均未带高熵字段。

测试结束后恢复 `FP-Test` 的屏幕设置并重开确认，清除两个配置的本机测试标记。仅本轮创建的 `FP-Local-Validation` 移入回收站。测试结论限于此 Mac、所列内核和配置，未测不同设备之间的误报率。
