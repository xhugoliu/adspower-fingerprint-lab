# 2026-11-20 · AdsPower 首轮指纹实验

## 环境

| 项目 | 实验条件 |
| --- | --- |
| 系统 | Apple Silicon Mac，芯片为 Apple M4，系统报告 macOS 27.2.1 |
| AdsPower | Global 8.9.23，实验期间客户端显示补丁 2.8.9.2 |
| 浏览器内核 | SunBrowser 156.0.8078.36 |
| 对照 | 同一台 Mac 上的 Chrome 157.0.8103.79，使用临时配置 |
| 测试范围 | 单个 AdsPower 测试配置 `FP-Test`，免费版。测试页面包括 FingerprintJS 官方演示和监听在本机回环地址的自建页面。 |

这份记录根据测试期间核对过的结果整理。临时采集文件已清理，复测时需要重新采样。演示页使用了当时在线版本，实验没有固定其 FingerprintJS 版本。

## 第一轮 · FingerprintJS 演示

1. 启动 `FP-Test` 并记录访客 ID 与调试字段。刷新页面，随后关闭配置并重开，比较三次结果。
2. 将时区由按 IP 取得的 `America/Los_Angeles` 改为自定义 `Asia/Shanghai`，重开后逐字段比较。

三次基线的访客 ID 相同。改时区后，新 ID 与基线不同。采集的 42 项中，这两次对照仅 `timezone` 的值不同。FingerprintJS 开源版将采集字段序列化后计算哈希，单字段变化即可改变 ID。 [FingerprintJS 源码](https://github.com/fingerprintjs/fingerprintjs/blob/master/src/agent.ts#L735)

## 第二轮 · 本机多上下文测试

自建页面采集主页面、同源 iframe、跨源 iframe 和 Dedicated Worker 的读数。两个网页源使用 `127.0.0.1` 与 `localhost`。服务端回显收到的 User-Agent、Accept-Language 和实际发送的 Client Hints。测试配置启动 3 次，每次采样 4 个页面，共 12 个页面、48 个执行上下文样本。

| 项目 | 结果 |
| --- | --- |
| 时区 | 48 个样本均报 `Asia/Shanghai`。分别取冬季和夏季日期，偏移量都为 UTC+8。 |
| 浏览器标识与语言 | 48 个样本的 JavaScript User-Agent 和首选语言分别与 HTTP 请求一致。实际收到完整版本 Client Hints 的 24 个样本也与 JavaScript 一致。 |
| 硬件信号 | AdsPower 的 WebGL 渲染器报 Apple A18 Pro，`navigator.deviceMemory` 报 8 GB。Chrome 分别报 Apple M4 和 16 GB。两者的 CPU 核心数与屏幕参数一致。 |
| Canvas | 默认设置下，本轮绘图的三次像素读取序列与 Chrome 对照完全一致。单独开启 Canvas 噪声后，四个上下文的读数都发生变化，各自经刷新和重开保持稳定。 |
| 存储 | 为本机测试页写入的 Cookie 与 `localStorage` 记录在同一配置刷新和重开后仍存在。 |

同一个配置的存储持久性已验证。跨配置的存储隔离需要两个可用于测试的配置，当前仍待实测。

## 第三轮 · 单项对照

保留同一测试配置和内核。每次调整目标设置后重开，采集基线和改变后的读数。浏览器恢复旧标签页时产生了带旧实验标签的重复记录，统计使用各轮按顺序取得的首组样本。

| 项目 | 步骤与实测结果 |
| --- | --- |
| 字体 | 在主页面比较候选字体与回退字体的文本尺寸。测试 246 个候选字体族，从默认切到一组自定义字体后，可识别数由 245 降至 226，三次相同。可布局 iframe 的复测取得了基线，自定义组受打开次数限制待补。 |
| 音频 | 用 OfflineAudioContext 渲染同一段三角波和动态压缩器链。开启 AudioContext 噪声后，`getChannelData()` 与 `copyFromChannel()` 的样本摘要在主页面和同源 iframe 都改变了，三次结果各自一致。 [FingerprintJS 音频采样实现](https://github.com/fingerprintjs/fingerprintjs/blob/master/src/sources/audio.ts#L651) |
| WebGL | 比较 WebGL 1 和 WebGL 2 的渲染器、扩展列表、`readPixels()` 与 PNG 导出。窗口使用 `toDataURL()`，Worker 使用 `OffscreenCanvas.convertToBlob()`。第一轮清屏绘图读数保持一致。换用着色器绘图后，开启图像噪声使主页面、同源 iframe 和 Worker 的像素读数均改变，三个样本都复现。PNG 导出与扩展列表保持一致，WebGL 1 有 39 项扩展，WebGL 2 有 36 项。 |
| 分辨率 | 默认模式下，`screen` 与 CSS 设备尺寸均报 `2304 × 1296`。配置改为 `1440 × 900` 后，两者分别报 `720 × 450` 与 `1440 × 900`，DPR 为 2。 |
| 定位 | 切换「每次询问」与「阻止」，分别查 Permissions API 并发起定位请求。两种模式都报 `prompt`。询问模式请求超时并返回错误码 3，阻止模式返回权限拒绝错误码 1。 |
| WebRTC | 使用本机页面创建未配置 STUN 的 PeerConnection，仅记录 ICE 候选类型。默认 `Proxy UDP` 三次完成收集，候选为空。`Real` 三次都返回 mDNS 主机候选。`Disabled` 三次都在 2 秒内未产生候选。公网和代理出口场景待测。 |

### 分辨率的窗口尺寸对照

使用同一个自定义分辨率配置，在同一进程内调整窗口，并用 `screen.width`、`screen.height` 与 CSS `min-device-width`、`min-device-height` 查询测量设备尺寸。

| 实测窗口外部尺寸 | JavaScript `screen` | CSS 设备尺寸 |
| --- | --- | --- |
| `1440 × 900` | `720 × 450` | `1440 × 900` |
| `962 × 781` | `720 × 450` | `1440 × 900` |
| `1100 × 900` | `720 × 450` | `1440 × 900` |

三次差异在窗口尺寸变化时仍然存在。比例与本机 DPR 吻合，DPR 或屏幕规格的影响需在额外对照中确认。

## 接下来优先验证

1. **分辨率一致性** — 在更多分辨率和 DPR 条件下重复比较两种读取路径，确认同一模式下的复现范围。
2. **WebGL 读取** — 固定绘图，逐项重复像素读取、PNG 导出和扩展查询，比较不同内核和多次进程重开后的结果。
3. **定位权限** — 在独立测试源重复对照 Permissions API 和定位请求，记录实际返回码。
4. **跨配置隔离** — 用两个可用于测试的配置访问同一个本机测试源，检查 Cookie、`localStorage` 和新一轮指纹采样。

## 实验收尾

免费账号触发每日打开次数上限，界面提示 24 小时后重置。测试设置已恢复，在管理页重新打开配置编辑器后核对了时区、WebRTC、定位、分辨率、字体、Canvas、WebGL 和音频。恢复后的浏览器重开受当日额度限制，待额度恢复后复验。
