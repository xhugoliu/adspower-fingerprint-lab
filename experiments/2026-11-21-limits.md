# 2026-11-21 · AdsPower 指纹配置能力边界

沿用[上一轮的三种读取方法](2026-11-21.md)。屏幕测试要求读数离开同机基线且各路径一致。WebGL 要求同一张画布的各条回读路径产生一致的改写结果。字体要求排除字体后，页面和 Worker 都无法再用该字体渲染。

在同一台 Apple M4 Mac 上运行 AdsPower Global `8.9.23`，补丁 `2.9.0.2`，测试配置使用 SunBrowser `157.0.8103.15`。Chrome `157.0.8103.79` 使用独立数据目录。通过[本机探针](../tools/probe/README.md)收集主页面、同源 iframe、跨源 iframe 和 Dedicated Worker。关键配置各启动两次，每次采三页。桌面页面保持 100% 缩放，实测 DPR 为 2。所有探针请求都在本机回环地址内。共 23 个批次、69 页，276 个上下文中收到 273 个结果，另外三个 iframe 超时。

## 屏幕分辨率的预设与随机模式

在同一桌面配置中，用 `screen` 属性、原型 getter、`matchMedia()` 和实际生效的 CSS 规则读取设备尺寸。每个 iframe 的视口单独校验，两类 iframe 的视口均为 `320 × 240`。桌面 `Based on User-Agent` 使用当前设备分辨率。 [AdsPower 屏幕设置](https://help.adspower.com/docs/browser_fingerprint#screen-resolution) · [CSS 屏幕尺寸定义](https://www.w3.org/TR/mediaqueries-4/#device-width)

| 桌面配置 | `screen` 与原型 getter | `matchMedia()` 与 CSS 规则 | 有效窗口上下文 |
| --- | --- | --- | --- |
| 按 UA 预设 | `2304 × 1296` | `2304 × 1296` | 17/17 一致 |
| 固定预设 `1440 × 900` | `720 × 450` | `1440 × 900` | 18/18 有两倍差异 |
| 随机，本次抽到 `1680 × 1050` | `840 × 525` | `1680 × 1050` | 18/18 有两倍差异 |

从预设下拉中选 `1440 × 900` 与上一轮手工填写同样尺寸的结果相同。随机模式在两次启动间保留本次抽到的尺寸。固定和随机配置都改变了公开读数，均出现 JS 与 CSS 不一致。

### Android 预设的屏幕尺寸

另建两个 `Based on User-Agent` 配置，分别手填 Android UA 和采用客户端自动生成的 Android 指纹。二者的 UA 输入都是 `Chrome/157.0.8103.15` 的 Android 字符串，各启动两次。自动组由客户端同时生成 Android Client Hints 和移动设备参数。 [AdsPower 配置说明](https://help.adspower.com/docs/creating_browser_profiles)

| Android 测试配置 | 四条设备尺寸路径 | DPR | 有效窗口上下文 |
| --- | --- | --- | --- |
| 手填 UA | `360 × 640` | `3` | 18/18 一致 |
| 自动生成 | `460 × 971` | `2.34375` | 18/18 一致 |

两组跨源 iframe 的 `screen.orientation.type` 都是 `landscape-primary`，`outerWidth/Height` 都是 `1200 × 1222`，与同机桌面 Chrome 对照的外窗读数相同。主页面和同源 iframe 则报告 `portrait-primary`，外窗尺寸与各自配置的设备尺寸一致。跨源 iframe 的尺寸和 DPR 读取仍符合表中结果。 [Screen Orientation 规范](https://www.w3.org/TR/screen-orientation/#screen-orientation-types)

手填组在窗口的 JS 和 HTTP Client Hints 中仍报 Linux 和非移动，自动组的窗口 Client Hints 则报 Android 和移动。两组 Worker 的 JS UA 版本均为 `157.0.0.0`，本机 HTTP 端实际收到的 Worker 请求均为 `157.0.8103.15`，共 12/12。Android 预设验证了移动尺寸在四条路径的一致改写，方向、外窗尺寸和 Worker UA 仍留下差异。 [User-Agent Client Hints 规范](https://wicg.github.io/ua-client-hints/)

## Canvas 与 WebGL 图像噪声叠加

同一桌面配置依次组合两个开关。WebGL 1 和 2 都绘制分段清屏与确定性着色器图案。逐像素对比数组直读及重复直读、PNG 解码、Canvas 2D 复制和 WebGL 2 像素缓冲区，并比对同配置 `Real / Real` 的摘要。独立 2D Canvas 对照保持 WebGL Image 为 `Real`，切换 Canvas 噪声后，36/36 次对应回读的摘要改变。 [AdsPower 指纹参数说明](https://localapi-doc-en.adspower.com/docs/Awy6Dg)

| Canvas / WebGL Image | 有效执行上下文 | 着色器回读 | 清屏回读 |
| --- | --- | --- | --- |
| Real / Real | 23/24 | 所有路径与预期一致 | 所有路径与预期一致 |
| Noise / Real | 22/24 | 所有路径与基线一致 | 所有路径与基线一致 |
| Real / Noise | 24/24 | 两代 API 的数组直读改变，其他路径与基线一致 | 所有路径与基线一致 |
| Noise / Noise | 24/24 | 两代 API 的数组直读改变，其他路径与基线一致 | 所有路径与基线一致 |

两种 WebGL 噪声配置的全部回读摘要相同。每组 432 条结果中有 96 条改写，来自两个 API 的着色器数组直读及重复直读。左上角为原点的 `(0, 63)` 从 `[17, 31, 47, 255]` 变成 `[50, 52, 53, 55]`。PNG、Canvas 2D 复制和 WebGL 2 像素缓冲区读回原值。Canvas 噪声对独立的 2D 场景生效，叠加后没有覆盖当前 WebGL 场景的其他读取路径。图案设计用于确定像素参考值，不能据此估算不同 GPU 的可区分性。

## 自定义字体与实际渲染

在同一桌面配置比较默认字体、移除苹方的 522 项自定义列表、包含苹方的 465 项自定义列表。保存后重开编辑器核实名单。两份自定义列表都未包含 `PingFangSC-Regular`。分别用 `local('PingFang SC')` 和 `local('PingFangSC-Regular')` 加载，将可加载的字体注册到 `FontFaceSet`，以拉丁和中文字符串比较实际 Canvas 度量。 [CSS Fonts 本机字体源](https://www.w3.org/TR/css-fonts-4/#descdef-font-face-src) · [CSS Font Loading](https://www.w3.org/TR/css-font-loading/#FontFace-interface)

| 配置 | 苹方普通 DOM / Canvas 度量 | PostScript 名称加载并渲染 |
| --- | --- | --- |
| Chrome 同机对照 | 8/8、12/12 可见 | 12/12 |
| AdsPower 默认 | 15/15、23/23 可见 | 23/23 |
| AdsPower 自定义排除 | 0/16、0/24 可见 | 24/24 |
| AdsPower 自定义包含 | 16/16、24/24 可见 | 24/24 |

四组共 83 个有效上下文中，按 `PingFang SC` 这一字体族名称直接调用 `local()` 均失败。按 `PingFangSC-Regular` 均可加载并渲染，所有度量向量都与同机 Chrome 一致。Arial 正对照均通过，不存在的名字均加载失败。Worker 无 DOM，各自定义组有两次跨源 iframe 的 DOM 布局未取到，Canvas 和 `local()` 数据均可用。该配置能改变普通字体匹配，按 PostScript 名称加载仍可使用宿主字体。

两组 Android 配置的 48/48 个执行上下文也能按 PostScript 名称加载并渲染苹方，度量向量与同机 Chrome 一致。

## 样本与收尾

桌面屏幕组使用 `limit-real-real-*`、`limit-fixed-*`、`limit-random-*`，移动组使用 `limit-android-*` 和 `limit-android-auto-*`。通过 `compare.py` 对比 `top.screen`、`crossFrame.screen` 或 `top.graphics`。例如，按以下命令对比移除和纳入苹方后的普通测量和实际字体加载。

```sh
python3 tools/probe/compare.py samples.jsonl limit-font-exclude-1 limit-font-include-1 \
  --field 'top.fonts.fonts.PingFang SC' --field 'top.fonts.localRender.PingFang SC'
```

原有配置未参与设置修改。本轮创建的三个配置已移入回收站。结果适用于本机的 SunBrowser 157，桌面实测 DPR 为 2，移动实测为 Android 预设。iOS、FlowerBrowser、其他宿主系统及不同设备间的误报率仍待实测。
